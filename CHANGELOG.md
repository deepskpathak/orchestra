# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Minimal L3 lesson graph (W9.4, `learnings.graph`, default `false`): lessons may carry `links: {files, symbols?}`, accepted through item edits (malformed links dropped). `retrieveByCode` in `src/learnings.ts` ranks lessons linked to the task footprint first within the retrieval budget; off, or `cleanRoom` (eval trials), retrieval is unchanged. Librarian seed prompt describes `links`.
- Oversight and throughput metrics (W7.2): `orchestra stats` prints interruptions (needs_human stops plus approval requests), review minutes (approval requested to decided), edits before landing (human, non-merge commits on the integration branch in that window), conflict rate, mean merge wait and cache-read share, `n/a` without data. `orchestra stats --json` emits `{versions, outcomes, oversight}`. The web dashboard's `/api/info` gains an `oversight` object (existing fields unchanged) and the run header shows the totals. Computed by `oversightSummary` in `src/dashboard-data.ts` on top of `oversightMetrics`; eval runs are excluded.
- M6 Throughput and oversight building blocks, all opt-in and off by default: the pure helpers `src/throughput.ts` (footprint overlap, merge batches, bisect, conflict rate), `src/oversight.ts` (risk tiers, approval rules, oversight metrics), `src/cost.ts` (plan cascade decision, budget lines, best-of-n gate, cache share) and `src/provider.ts` (`ModelProvider`, default Claude adapter), wired into the conductor by the entries below.
- Conductor wiring for cost control and the provider adapter (W6.3 to W6.6, W8.1), all off by default. `planner.cascade` drafts the plan with a cheap model and escalates to the harness planner only on low confidence or a failed `planChecks`, logging a ledger outcome per run. `budgets.workerPrompt` puts turns and dollars remaining in worker prompts, passes `--max-turns` (new optional `AgentRequest.maxTurns`) and fails a task that reaches its cap instead of repairing it. `bestOfN` runs several worker samples only where a test command or scenario check exists and selects by tests before judging. `cache.discipline` makes sibling requests identical and starts one worker before fan-out. `Run.cacheReadShare` is recorded whenever token usage is reported. Agent calls go through `ModelProvider` (`provider`, default `claude`, unchanged behaviour). Keys are in `docs/configuration.md`.
- Conductor wiring for throughput and oversight (W6.1, W6.2, W7.1), all off by default. `throughput.footprintScheduling` runs only footprint-disjoint tasks in parallel (via `canStart`) and appends a decision log of merged dependencies to dependent worker prompts. `throughput.batchMerge {enabled, maxBatch}` merges disjoint batches, runs post-merge tests once and bisects on failure (`bisectBatch` now skips re-testing the right half when the left half passed, and the surviving tasks are tested once more as a union before they land); `Task.mergeWaitMs` records merge wait. `oversight.riskTiers` holds high-risk passing tasks as the new `awaiting_approval` status until `orchestra approve <runId> <taskId> --by <name>`, which refuses the requester (`Run.requestedBy`) and agent roles. `Run.conflictRate` is recorded for every run and in the `run.end` event. Keys are in `docs/configuration.md`.
- L2 atlas query command (W9.3, `context.atlas.query`, default `false`): `orchestra atlas find|neighbors|impact|tests <symbol-or-path>` renders tree output from `src/atlas-query.ts` with an 80 line cap and a truncation marker, marks files modified in the calling worktree (`git status --porcelain`) as `(stale: read the file)`, and adds advisory "callers not updated" notes to `impact` (it never gates a merge). With the atlas disabled or not built it prints a hint and exits non-zero. The key only controls whether worker and judge prompts mention the command; usage guidance is in `harness/v1/tools.md`. New bench arm `atlas-l0-l1-l2`.
- Optional external atlas inputs (W9.5, `context.atlas.external`: `off` default, `auto`, `ctags`, `graphify`): `src/atlas-external.ts` detects universal-ctags through an injected exec, parses `ctags --output-format=json` and a graphify `graph.json` into atlas nodes and edges, and merges them on load (the cache keeps the built-in graph). A missing source falls back to the built-in atlas with a logged reason; nothing is required and there is no network. Docs list ctags, graphify and external MCP code-graph server (codegraph, Serena) opt-ins.
- Verification-mode measurement (H2): runs record the M4 modes enabled when they started in `Run.verificationModes` (`panel`, `agentic`, `contracts`, `oracles`, `mutation`; absent when none). `orchestra stats` now prints the merged-but-wrong rate (landed runs that were reverted or needed a later fix) and the judge agreement with bench hidden checks per mode, so each mode can be compared with `none`. A run using several modes counts under each. `OutcomeMetrics.byVerification` carries the same data.
- W4.4 oracle wiring: with `verification.oracles.enabled`, tasks with contract invariants are graded by oracle files written by a separate session outside the worker worktree, plus a differential run against the run base commit; worker tests are listed as non-grading.
- Mutation score per run (W4.5, `verification.mutation.enabled`): after all merges, `src/mutation.ts` mutates the source files the run changed (`===`/`!==`, `<`/`<=`, `>`/`>=`, `+`/`-`, `&&`/`||`, `true`/`false`, never inside strings or comments) in a scratch worktree, and counts a mutant killed when the test command or any scenario `check` fails. The result is stored on `Run.mutation`, logged as an event and shown in `orchestra status` and the run summary. With `failBelowFloor` a score under `floor` fails the run; otherwise it only reports. No mutants (or no checks, or a baseline that already fails) is reported as skipped and never fails the run.
- Machine-readable acceptance contracts (W4.3, `verification.contracts.enabled`): the planner may return `ambiguities` and per-task `invariants`; an unresolved ambiguity fails planning before any worker starts, and `runs/<runId>/contract.json` freezes the criteria (ids like `T1.c1`, status `failing`/`passing`) with its sha256 on `Run.contract`. Workers can only flip failing to passing (`src/contracts.ts`); the guard denies writes to contract files and the integrity monitor flags diffs that touch one.
- M4 Verification config scaffold: an opt-in `verification` block (`contracts`, `panel`, `agenticJudge`, `oracles`, `mutation`), all disabled by default and merged key by key, with optional `Verdict.panel`, `CriterionResult.evidence`, `Scenario.check`, `Run.mutation` and `Run.contract` fields. Keys are documented in `docs/configuration.md`; behaviour lands in later tasks.
- Agentic judge (W4.2, `verification.agenticJudge.enabled`): the conductor runs every scenario `check` command and the test command in the task worktree (each bounded by `checkTimeoutMs`) before judging and passes the results to the judge as an EXECUTED CHECKS section. The judge is told to run builds, tests and scenario scripts with Bash and to return `evidence` per criterion; a criterion that passes without evidence adds the advisory issue `Criterion passed without executed evidence` (it does not fail the task). The planner schema accepts an optional `check` per scenario. Helpers live in `src/judge-checks.ts`. Disabled, the prompt and verdict are unchanged. With the panel also on, a criterion keeps the evidence of the first judge that sided with the majority.
- Judge panel (W4.1, `verification.panel.enabled`): each configured judge scores per criterion under a lineage-specific framing line, `src/panel.ts` aggregates majority and disagreement, and a tie on any criterion escalates once to `escalateModel` (default the harness judge model), whose verdict decides. `verdict.panel` stores `{votes, disagreement, perCriterion, escalated}` and a log event reports the disagreement. Contrastive repair also runs the comparison in both orders and picks nothing when they disagree (position bias). Disabled, judging is unchanged.
- M3 Evolution, all opt-in and off by default (config keys in `docs/configuration.md`, behaviour in `docs/self-improvement.md#cycle-controls-m3`).
- Time-split eval sets (W3.1): `evolve.splits` orders cases by `createdAt` into feedback, validation and a locked holdout (default 30/50/20). The evolver sees feedback cases only, the holdout confirms a promotion, and below `signoffBelow` (12) cases promotion needs a human.
- Harder and imported eval cases (W3.2): `orchestra evals add "<goal>"`, human-fix harvest with `evals add --from-run <runId> --fix <commit>` (the fix diff becomes the case `reference`), `evals list --regression|--tag`, and `orchestra evals audit` for solution leakage in goals, references and lessons. Audit exits 0 when clean, empty or uninitialised and 1 with findings; CI runs it. Unknown `evals` subcommands are rejected. Logic is in `src/evalcases.ts`.
- Cascade screening (W3.3): `evolve.cascade` runs a smoke test (guards, checklist, one case), a minibatch against the parent, and full validation for the top finalists only; a cycle with no viable candidate spends nothing on full validation.
- Sequential testing and budget cap (W3.4): `evolve.sequential` evaluates in rounds and stops when the paired CI settles; `evolve.budgetUsd` is a hard per-cycle cap.
- Cost in the objective (W3.5): `evolve.cost` adds a SICA-style utility and rejects variants whose cost rises more than `maxCostRisePct` without a matching gain.
- Pareto archive (W3.6): `evolve.pareto` keeps variants best on at least one validation case, picks parents by Pareto wins plus descendant success, shows the evolver the scored archive history and keeps `stepping` variants in `archive.json`.
- Lesson hygiene (W3.7): the librarian now returns item edits (add, update, remove by lesson id) applied by `applyLessonEdits`, so no code path replaces a domain's lessons from model output. Lessons carry stable ids and helpful/harmful counters (old files load with zeros). Opt-in `learnings.expiryDays` (default 0 = off) expires stale or harmful lessons. New `orchestra evals ablation` replays the holdout with and without learnings and reports the paired delta and CI.

### Changed

- Docs: whitepaper and blog updated for the M3 to M6 milestones (the whitepaper header now names 0.6.1 plus the unreleased work). Factory Eval cases are no longer described as successes only (hand-added cases, human-fix harvests, `evolve.splits`, `orchestra evals audit`), the blog no longer says "No containers" (opt-in `--sandbox`, not yet exercised against real backends), and the opt-in M3 cycle controls, M4 verification modes, batch merge and risk tiers are mentioned where the text had gone stale.

### Fixed

- Conductor state cleanup: the scheduler's in-flight set is now the single `inflight` map (the mirrored `inflightIds` set is gone); the dependency decision log has its own optional `throughput.decisionLog` key (unset follows `footprintScheduling`, so default prompts are byte-identical); and the per-call hot paths (worker caps, budget state, batch flush, atlas hint) use one config snapshot taken at run start instead of re-reading `config.json` on every agent call.
- Batch merge: a batch with no bad task no longer re-merges the landing set after testing it, so the final integration HEAD is the commit that was tested. Repair notes for bad tasks now carry the output of the failing run that implicated them, and tasks dropped by the union check carry the output that rejected them (previously a stale or empty tail from the last run, often a passing one).
- Atlas external sources (`context.atlas.external`): ctags now runs on the atlas commit's own files (written to a scratch directory and fed through `-L -`, with `.git`, `.orchestra` and `node_modules` excluded) instead of `ctags -R .` over the live checkout, and its output is cached by sha in `.orchestra/atlas-ctags/` so it no longer rescans on every conductor start. graphify `graph.json` is read as committed at the atlas commit (falling back to the checkout's copy with a log line). `orchestra atlas` now passes the same external options as the conductor, so CLI queries see the same graph agents were given.
- Oversight metric "edits before landing": human commits are now counted on the integration branch's first-parent line only, so worker commits made under the developer's own git identity on merged task branches no longer count as human edits, and the 1000 ms slack before the approval window is gone.
- `orchestra approve`: when the run recorded no requester (`unknown`), the four-eyes check cannot be applied, so approval now warns on stderr and logs the same advisory in the run events instead of passing silently. The docs, README and CLI help now state plainly that the check is advisory (free-text names), not authenticated identity.
- Best-of-n: the parallel samples now split the remaining worker turn and dollar cap (`budgets.workerPrompt`) instead of each getting all of it, so n samples no longer spend about n times the hard cap. Sampling uses `Promise.allSettled` with `try/finally` cleanup, so a sample that throws no longer discards the others or leaks its worktree and branch, and a throwing runner no longer leaves a phantom active agent.
- Risk tiers: a run whose only unmerged tasks are held for approval (or blocked behind one) now ends as the new run status `awaiting_approval` instead of `failed`. Satisfaction, the mutation pass and `learn()` are deferred rather than computed as if the held task never landed, and `orchestra run` exits 0. `orchestra approve` of the last held task records satisfaction and sets the run to `done` (or `failed` when blocked dependents never ran; approval does not restart them). Mutation and learning are not re-run after approval. Behaviour with `oversight.riskTiers` off is unchanged.
- `orchestra atlas find|neighbors|impact|tests` now works from a task worktree, which is where the prompt hint tells agents to run it. The command resolves the main checkout (via `git rev-parse --git-common-dir`) for `.orchestra/` config and the atlas cache, and queries the worktree's own HEAD and modified files. Previously it died with "disabled" or "no atlas" because `.orchestra/` does not exist in a worktree.
- Batch merge: new task worktrees (attempts, contrastive B, best-of-n samples, the mutation scratch tree) now branch from the last integration commit whose tests passed instead of the integration HEAD, so a task that starts while a batch is under test can no longer inherit a transient or rejected merge. The integration worktree is also reset to that commit if a batch throws.
- Agentic judge: with `verification.agenticJudge.enabled` the planner request now asks for the optional scenario `check` command (previously nothing in the prompt mentioned it, so the executed-checks section was almost always empty). The ask is part of the request body, so it applies to existing harness copies too; with the agentic judge off the planner prompt is byte-identical. The shipped `harness/v1/planner.md` is unchanged.
- Oracles: the differential probes now run against the commit the task started from (its base), not the run base commit, so changes landed by earlier tasks it depends on are no longer reported as `differential mismatch`.
- Mutation pass and agentic scenario checks no longer block the event loop: they use a new async `git.runTestsAsync` (own process group, killed on timeout) instead of `spawnSync`, so the TUI and web dashboard keep updating. Each mutant check is bounded by the new `verification.mutation.mutantTimeoutMs` (default 60000, was the 10 minute `runTests` default); a timeout counts as killed. The unmutated baseline run and the main test command are unchanged. `runMutation` and `runScenarioChecks` now return promises.
- Judge panel: per-criterion votes are now matched onto the acceptance criteria by the judge's own 1-based `index` (panel judges are asked for it), then by normalised text, then by position when the count matches; unmatched entries are dropped instead of becoming keys of their own, so differently worded judges no longer produce disjoint keys that look like lone votes. A criterion needs a true majority of all judges (a criterion some judges did not answer, or none did, is a split and escalates), the synthetic `overall` answer is only tallied when no judge keyed real criteria (and can no longer be added as a criterion with a bad index), and non-finite scores are ignored in the mean. Panel off: prompts and schema are unchanged.
- Contracts (W4.3): the contract was write-only. With `verification.contracts.enabled` the conductor now re-verifies `Run.contract.sha256` against `contract.json` before judging (a mismatch fails the attempt with an integrity flag and restores the file; the worktree diff pattern could never fire because `.orchestra` is outside every worktree), flips a task's criteria to `passing` through `applyContractUpdate` when it merges and records the new sha256, and reads the judge's acceptance criteria and the oracle author's invariants from the verified contract file. Still opt-in.
- Mutation scanner: it no longer mutates TypeScript generics (`Promise<void>`, `Map<string, number>`, generic arrows), shifts (`<<`, `>>`, `<<=`), JSX tags, regex literals or `${}` template expressions, and an apostrophe after a word character (JSX text, prose) no longer opens a string that swallows later code (quoted strings also end at a bare newline). A mutant whose run fails with a syntax or compile error is classified invalid and excluded from the score instead of counting as killed; `Run.mutation.invalid` reports how many, and a pass where every mutant is invalid is recorded as skipped.
- Mutation: a skipped pass (no commands, failing baseline, zero mutants) used to record score 1.0 and pass, which read as proof of strong tests. `Run.mutation` now has an optional `score` and `pass` and a `skipped` reason; the CLI summary, TUI and web dashboard render it as skipped and `failBelowFloor` ignores it.
- Mutation: the changed-file list now excludes files deleted on the integration branch (`git diff --diff-filter=d`), and a file that cannot be read is logged and skipped on its own instead of aborting the whole pass (previously one deleted file threw ENOENT and the mutation gate was silently disabled).
- Verification isolation: oracle tests and probes, agentic scenario `check` commands and mutation runs execute worker-written code, but ran with the full orchestrator env. They now get `scrubVerifierEnv` (`scrubWorkerEnv` plus no `ANTHROPIC_*` or `CLAUDE_*` credentials; PATH, HOME and the rest are kept). `git.runTests` takes an optional env. These commands are still not routed through the worker sandbox (see `docs/isolation.md`); the main test command keeps its existing env.
- Oracles: an exception in the oracle pass (git worktree add, creating the oracle directory, a missing base ref) is now caught, logged and treated as no oracle evidence, like a failed mutation pass, instead of aborting judging. The throwaway base worktree is created inside the `try`, so it is always cleaned up.
- Oracles: when the oracle author session fails or writes no files, the task is graded without oracle evidence (the log message already said so). Previously the empty result was recorded as a failed independent run and failed a healthy task.
- Budget cap: a validation cut short by `evolve.budgetUsd` (or an infrastructure failure) now saves its finished per-case results on the candidate (`partialEval` in `archive.json`). The next cycle resumes that candidate while the incumbent is unchanged, skipping the evolver call and replaying only the unfinished cases, instead of discarding the work and repaying for it.
- Cascade smoke test: a candidate is rejected for failing the smoke case only when the incumbent passes it (one baseline replay, cached for the cycle). Smoke rejections carry `rejectKind: "smoke"` in `archive.json` and are no longer fed back to the evolver as "previously rejected, do not repeat".
- Evolve: incumbent replays are cached per cycle (smoke baseline, minibatch, screening, every finalist, holdout) so the same incumbent/case pair is paid for once. Reused replays keep their nominal cost for the cost gate and are not charged to `budgetUsd`. New opt-in `evolve.regression.enabled` always replays regression-tagged validation cases (W3.2), and the evolver prompt guard now uses `promptHasNoHoldout`. `recordLessonOutcome` is removed: lesson helpful/harmful counters are already updated through the librarian's `helped` edit, and nothing produced an objective per-lesson outcome to feed a second path.
- Splits: the holdout is now actually locked from the evolver. Assignments are sticky (persisted in `.orchestra/splits.json`, new cases fill the short quota), so a holdout case never slides into feedback as cases arrive. Runs that produced a holdout case are excluded from the evolver's metrics, repair notes and learnings summary (`summarizeLearnings` takes an exclusion set), and the evolver prompt is checked with `holdoutLeaks` and not sent if it names a holdout case. `holdoutLeaks` matches ids as whole tokens, so a short id no longer blocks every prompt. `evals ablation` uses the same sticky holdout.
- Pareto: a variant bred from a stepping stone is now integrity-checked against the live incumbent (checklist lines, `passThreshold`, models) in the smoke test and before promotion, not only against its parent, so it can no longer silently drop incumbent guards. The evolver prompt labels the files as the `PARENT HARNESS` (not live) and lists the incumbent's constraints.
- Sequential testing: an early stop can no longer promote on fewer cases than `evolve.minCases`. The round check is skipped until `minCases` cases are evaluated, and the promotion gate receives the configured floor instead of one clamped to the evaluated count.
- Sequential testing: the per-round CI is now widened for the number of planned rounds (Bonferroni-style alpha spending, `wideningFactor`), so peeking after every round no longer inflates the false promotion rate. `niMargin` is now the reject threshold (reject once the upper bound is below `-niMargin`); the old `hi < 0 || hi < -niMargin` made the margin dead logic.
- Pareto: `selectParent` only breeds from archive entries with status `promoted` or `candidate` (the front is computed over those) and whose harness directory still exists, so a rejected, retired or deleted variant is never chosen as a parent. With no eligible entry the incumbent is used.
- Evals harvest: the human-fix diff is read from git's stdout only (stderr no longer leaks into the stored reference) and `evals add --from-run ... --fix` now fails with a clear message when git fails or the fix commit does not descend from the run's base, instead of storing git's error text or an unrelated diff as the reference.
- Evals audit: the solution-leakage check now compares goals and lessons with the added (`+`) lines of a reference diff only, whitespace-normalised. Quoting existing code (context or removed lines) in a goal is no longer flagged as a leak. Plain-text references still use every line.
- Atlas: the atlas schema is now version 2 and persists `skipped` (oversized, binary or unreadable paths). Older caches are ignored and rebuilt, and incremental builds re-extract only changed and genuinely new paths instead of re-reading skipped files every time.
- Atlas TS/JS extractor: class methods are only the lines at the class body's own indent (learned from the first member line, as the Python extractor does), so calls such as `emit({` or `describe('x', function () {` inside a method are no longer recorded as methods.
- Atlas tests edges: the test subject is derived only from real test naming patterns (`.test`/`.spec`, `_test`, `test_` prefix, Java `Test`/`Tests`/`IT` after a lowercase letter or digit), so names like `EDIT.java` are no longer mangled, and a name-based edge is limited to the test's own directory or the subtree above its `tests/` directory instead of any directory in the repo.
- Exploration metrics: planner-declared `footprint.files` no longer replace the title-derived "planned" set in the ledger. Planned keeps its meaning with the atlas on or off; declared files (intersected with tracked files) go in a separate `footprint.declared` field and a second "declared" line in `orchestra stats`.
- Bench: `orchestra bench --reference <arm>` now fails before running when the arm is not among the arms in the run, instead of rendering every row as `(reference)`.
- Atlas Go imports: resolution uses the `go.mod` module path when present (stdlib and external imports get no edge) and otherwise needs at least two trailing path segments, via a precomputed directory-suffix map instead of scanning every directory per import.
- Atlas TS/JS imports: the import/export regex is anchored per statement and cannot span another import or export keyword, so in semicolon-less code an earlier `export ...` no longer swallows the next import.
- Atlas L1 task pack: skeletons come from the base-commit atlas, so a file changed on integration is now annotated "changed since base; symbols and lines as of the base commit" instead of looking current.
- Atlas build: blobs are sized with `git cat-file --batch-check` and only those within 256KB are read, binary extensions are skipped up front, and a failed chunk read degrades to per-blob reads, so large or binary files can no longer overflow the buffer and abort the build.
- Atlas cache: `loadOrBuildAtlas` picks at most 8 candidates cheaply (ancestors from one `git rev-list`, then most recently written caches) before diffing instead of diffing every cached sha, and prunes `.orchestra/atlas` to the 16 most recent files.
- Sandbox: the srt and claude write policy now includes the shared git common dir (hooks and config stay read-only inside it), so a worker's `git commit` in a worktree can write objects, refs and worktree metadata. Matches the docker backend.
- Sandbox: `permissions.deny` rules now use Claude Code's absolute-path form (`Read(//home/u/.ssh)`, not `Read(/home/u/.ssh)`, which means settings-relative) and add a `/**` variant so directories cover their contents. Globs such as `**/.env` are unchanged. Unverified against a live Claude Code, so both the bare and `/**` forms are emitted.
- Sandbox: `srt --settings` now gets a file in srt's own shape (top-level `network.allowedDomains`, `filesystem.allowWrite/denyRead/denyWrite`) instead of the Claude Code shape. The `claude` backend keeps the Claude shape. Key names follow the sandbox-runtime README as recalled and are unverified against an installed srt.
- Sandbox: settings are no longer written to the worker-writable `<worktree>/.claude/settings.local.json` and merged with whatever was there. The `claude` backend passes the sandbox block inline in `--settings`, built fresh from the policy; the `srt` backend gets a fresh file under `.orchestra/sandbox/`, which the worker cannot write. Repo or worker content can no longer persist `excludedCommands`, `allow` rules or hooks into the sandbox settings. Residual: Claude Code still merges the repo's own project settings by design, so a hostile repo `sandbox.excludedCommands` is not stripped under the `claude` backend; prefer `srt` or `docker` for untrusted repos.
- Sandbox: judge sessions (same task worktree as the worker) no longer inherit the worker's sandbox settings, because no `settings.local.json` is left in the worktree any more. The `.git/info/exclude` entry for it is dropped. A test checks that no session cwd contains the file.
- Conductor: the git common dir for the worker sandbox policy is resolved once per run instead of running `git rev-parse` on every agent call.
- Sandbox pre-flight (docker): the read-probe canary used to sit under the temp directory, which docker mounts read-write, so the probe could never pass against a real daemon. It now lives outside every mount (`/var/tmp`, else the home directory); if none is usable the probe is skipped with a warning. `PreflightResult` gains `warnings`, logged by the conductor.
- Sandbox pre-flight: a failed network probe no longer counts as BLOCKED by itself. The same fetch runs unsandboxed first as a positive control; if it also fails the result is reported as inconclusive (no connectivity), the sandboxed network probe is skipped, and a warning is logged that network confinement is not verified. The control is one extra outbound request to the probe host by the orchestrator process. Tests use the injected exec only.
- CLI: `orchestra run` no longer drops goal words that equal the `--sandbox` or `--sandbox-image` value (`orchestra run turn off the cache --sandbox off` kept only `turn the cache`). The flag and its value are removed by position.
- Docker backend: containers now run as the invoking `uid:gid` (`--user`, with `HOME` set to the temp mount) so files in the worktree are not root-owned. New `--sandbox-network <net>` (default `none`, unchanged) lets the user pick a docker network that can reach the model API. With `none` the pre-flight logs a clear warning that a claude worker cannot call the model; on a non-`none` network it skips the network probe and warns that docker does not enforce the host allow-list. The default still cannot run a claude worker without an image-provided route; that is documented, not solved. Behaviour is unchanged when docker is not selected.

### Added

- W9.1 and W9.2 Repo Atlas (opt-in, off by default via `context.atlas`): a deterministic, commit-keyed code graph (`src/atlas.ts`, regex extractors for TS/JS, Python, Go, Java and Rust with a file-level fallback) stored at `.orchestra/atlas/<sha>.json` and rebuilt incrementally from `git diff --name-only`. It never indexes `.orchestra/`, `.env*` or the guard's secret patterns, and is outside `EVOLVABLE_FILES` and the scorer. No new dependencies or network calls.
- W9.1 L0 ranked map: a tree outline ranked by personalised PageRank seeded by goal terms, within `mapTokens` (default 1024). It replaces the planner's first-300-files list and goes in the shared worker prefix, byte-identical across workers.
- W9.2 footprints and L1 task packs: optional `footprint: { files, symbols? }` per task in the plan schema, and a per-task pack (footprint signatures, 1-hop callers and importers, related tests, files changed on integration since run start) in the worker prompt body under `packTokens` (default 1500). The judge does not get the pack.
- W9.1 CLI: `orchestra atlas build` and `orchestra atlas stats`.
- W9 bench ablation: `bench/arms.json` gains `atlas-off`, `atlas-l0` and `atlas-l0-l1` arms that set `context.atlas` per arm (marked `optional`, so a plain `orchestra bench` still runs only `default`). `orchestra bench` gains `--reference <arm>` and prints the paired table for any multi-arm run and for `--report` (reference `full`, else the first arm); `armConfig` now merges nested config objects recursively. docs/bench.md explains how to read tokens per accepted merge (H6) and footprint recall (H7) from the paired report and `orchestra stats`.

## [0.6.0] - 2026-10-22

### Added

- Wider evolvable harness surface (#9). Three small optional files, `tools.md` (worker and judge), `style.md` (worker) and `checklist.md` (judge), can now be tuned by the evolver without rewriting a role prompt. Missing files are treated as empty, and a variant may not remove lines from `checklist.md`. Skills and executable scripts remain out of scope.
- Multi-candidate evolution (#8). The opt-in `evolve.candidates` setting (default `1`, behaviour unchanged) makes the evolver propose k variants per cycle, screen each on `min(2, sample)` eval cases and drop any that regress a case the incumbent passes, compose the survivors into one variant, and decide with the usual `promotionDecision` rules. Archive entries gain optional `parents` and `screenScore`, and screened-out candidates appear under PREVIOUSLY REJECTED VARIANTS.
- The seed evolver prompt documents the `{ variants: [...] }` output, the different-weaknesses rule and `COMPOSE VARIANTS`.
- Contrastive repair (#11), opt-in via the `contrastive` block in `.orchestra/config.json`. On a repair attempt in a repo without a `testCommand`, two workers try the task in separate worktrees (one follows the repair notes, one takes a different approach) and one comparison judge call picks a winner. The winner's branch continues, the loser is deleted, and the judge's reasons feed the librarian as lesson evidence. The task drawer shows "Picked A over B because ...". Disabled by default; `passThreshold` is never lowered.

## [0.5.0] - 2026-10-22

### Added

- Per-domain learning libraries (#10). The planner tags each run with a short `domain` slug (existing domains plus at most one new one per run), stored on the run. Lessons live in `learnings/<domain>.json` plus `learnings/_global.json`, and the `learnings.md` mirror is grouped by domain.
- Every lesson carries `evidence` (the run or task that supports it) and a `hits` count. The librarian must cite evidence, and lessons without it are dropped.
- `orchestra learnings --domain <slug>` filters the list to one domain.

### Changed

- Prompts receive the run's domain lessons then global ones under a token budget, instead of the whole store.
- The 25-lesson cap applies per domain, and the least recently evidenced lessons are dropped first.
- `orchestra evolve` receives a per-domain summary (counts and top lessons) instead of the full store.
- An existing `learnings.json` is migrated to `_global.json` on first read.

## [0.2.0] - 2026-10-22

### Added

- Community and project health files: contributing guide, code of conduct, security policy, issue and pull request templates.
- GitHub Actions CI (`npm test` on Node 24) and a branching section in the contributing guide (one `iter/<topic>` branch per iteration, changes land by pull request).
- Token and cache usage per agent session in the ledger, and cache hit ratio in `orchestra stats`.
- Tiered judging (`judgeTiers` in `.orchestra/config.json`): a cheap judge model first, escalating to the strong judge on test failure, borderline scores or open issues. Off by default.
- Research notes and a ranked improvement backlog in `docs/research/cost-accuracy-speed.md`.
- Per-criterion judging: verdicts may carry an optional `criteria` list (pass, score and note per acceptance criterion), the score is aggregated from it, and repair notes list the failing criteria.
- Planner fast path (`fastPath` in `.orchestra/config.json`): a small single-concern goal gets exactly one task and no hidden-scenario requirement. Off by default.

- Progress file for repair attempts at `.orchestra/runs/<run>/progress/<task>.json`, holding the previous diff summary and judge issues. The repair prompt points at it instead of inlining long text.
- Deterministic pre-judge checks (`preJudge` in `.orchestra/config.json`): an optional lint command and a check that new exports under `src/` come with a changed test file. Failures go straight to repair without a judge call. Off by default.

### Changed

- The judge now retries once on failure and never scores a worker 0.00 for a judge error.
- Role prompts are ordered from stable to volatile content so their prefix can be shared and cached.
- Harness promotion requires a minimum number of eval cases (`evolve.minCases`, default 5) and a gain above the observed spread. `evolve.sample` defaults to 5.

## [0.1.0]

First release.

### Added

- **Software factory**: a zero-dependency TypeScript CLI (Node 23.6+, native type stripping) and Claude Code plugin. The conductor runs planner, then parallel workers in isolated git worktrees, then tests and a judge against hidden holdout scenarios, a repair loop, a serialized merge queue with post-merge tests, and a librarian that records learnings.
